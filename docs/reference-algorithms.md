# 処理方式と出典

更新日: 2026-10-02（日本時間）

## キーの判定と同期

キー情報は手動指定、ファイル名、音声解析の順に優先する。ファイル名では音名・長短調、異名同音、Camelot、Unicodeの変化記号を扱い、曖昧な名前は音声解析へ回す。

音程付き素材はメジャー基準に揃える。マイナーは平行調のメジャーに読み替え（A minor → C major）、元の判定情報を保持する。この読み替え自体では音程を変えない。単音・長短不明のルートは、同じルートのmajorを処理上の基準にする。

キー同期では素材と合わせ先の主音間の最短の半音差を計算する。ちょうど6半音の場合は下方向を選ぶ。ファイル名・手動指定・音声推定のいずれも同じ計算を使い、素材全体に同じ補正を適用する。解析でキーを保留した素材は自動移調しない。

自動の合わせ先はユーザー素材をデモより優先し、その中で長短調が分かる素材と明示されたキーを優先する。選ばれた基準素材自体は移調しない。合わせ先は手動でも指定できる。

例えばA minorはC major基準なので、合わせ先C majorなら0半音、D majorなら＋2半音となる。素材全体の移調では、素材内の長短関係やコード進行は変わらない。

## 音声解析

`js/key-analysis.js` は、窓をかけた音声のFFT、スペクトルのピーク検出、12音の分布（chroma）、キーのプロファイルとの照合を組み合わせる。chromaは音声から元のキーを推定する段階で用いる。

- FFTには **fft.js 4.0.4（MIT）** を使用する。上流本文にブラウザ用の接続部分とMIT表示を加え、`vendor/fft.js/fft.js` に同梱する。固定コミット、取得元、ハッシュは [provenance.json](../vendor/fft.js/provenance.json)、ライセンス全文は [LICENSE](../vendor/fft.js/LICENSE) に記録する。
- キーの重みにはPartitura v1.2.1掲載のKrumhansl–Kessler profilesを使用する。major/minor各12個、計24個の数値をJavaScript配列に転記し、数値は変更していない。取得元、著作権表示、変更範囲、Apache-2.0の利用条件は [第三者表示](../THIRD_PARTY_NOTICES.md#krumhanslkessler-profiles--partitura) に記載する。
- スペクトルのピークから音高クラス分布を求める方式は、Essentiaの [HPCP](https://essentia.upf.edu/reference/std_HPCP.html) と [Key](https://essentia.upf.edu/reference/std_Key.html) の説明を参考にする。Essentiaのライブラリ、WASM、C++ソースは同梱・読み込みしていない。

## フレーズ生成と再生

`js/generator.js` は素材と設定、SEEDから断片の配置を生成する。各レーンは1小節の単位A、A'（Aの最初の3拍を残し、最後の1拍を別のリズムと断片に差し替え）、B（Aと別のリズムで素材の別の位置から始める）、B'を作り、4小節では A → A' → B → A、2小節では A → A'、8小節では A → A' → B → A → A → A' → B' → A' と並べる。単位はループの長さに関係なく同じ順に乱数を引くため、小節数を変えてもAとA'は変わらない。FM音源は合成時の音符の開始・終了位置（`noteSegments`）を保持し、均等分割の代わりに連続する1〜3音のまとまりで切る。まとまりに加えるのは、直前の音の終わりから16分音符1つ以内に始まる音だけで、全体を8ステップ（半小節）以内に収める。長さは合成時の16分音符の格子（`segmentsSteps`）で数えるため、ループのテンポを変えても配置は変わらない。まとまりは鳴り終わるまで次の発音を置かず、元の並びを続けるか、同じまとまりを繰り返す（連打）か、元フレーズで同じ拍内位置（16分音符4つ単位の位置、なければ表拍・裏拍）にあった音へ飛ぶ。複数の音のまとまりは元の8分音符の格子とずれる位置では続けず、飛ぶか最初の1音だけを繰り返す。LOCKされたレーンは元の配置を保持する。乱数更新に使用するMulberry32の出典と利用条件は [第三者表示](../THIRD_PARTY_NOTICES.md#mulberry32) に記載する。

各素材には役割がある。手動指定を優先し、ドラムに分類した素材はドラム、それ以外は名前・デモの種類・FM音源のオクターブ（1〜2）からベースと主役を1つずつ自動で選び、残りを合いの手とする。自動の選択では、読み込んだ素材とFM素材をデモより優先する（主役は名前の手がかりがあるもの、ベースは低いFM音源を先に選ぶ）。ベースは専用のリズム単位を使い、小節の頭を必ず鳴らし、音を少し長めに保ち、同じ断片を繰り返しやすい。下方向のオクターブ移動はせず、上方向は裏の8分だけにする。低いFM音源があればベースに優先する。ドラムは小節の頭を必ず鳴らし、Aの頭を素材の先頭（断片0）にし、オクターブ移動をしない。主役はBの小節で頭を強制せず、頭の発音確率を0.55倍にする。主役を先に生成し、主役が鳴っている16分音符の区間と発音位置を記録する。合いの手は1.3倍の密度で作ったあと、主役が鳴っている位置では12%、主役が発音する拍の中では60%、主役が発音しない拍では100%の確率で残す。この抽選は単位（A・A'・B・B'）と拍内位置から決めるため、同じ単位が戻ると同じように返事をする。主役の生成は他の素材に依存しないため、合いの手やベースを追加・削除しても主役は変わらない。

小節末の扱いは全レーンで共有する。breaksから休符の長さ（ループ長×0.5×breaksが1.5ステップ未満なら休符なし、3未満なら8分、6未満なら1拍、それ以上は拍単位に丸め、最大でループの半分）を求め、4小節以上では2小節ごと、2小節以下では1小節ごとの区切りのうち、SEEDで選んだ区切りで終わるように置く。4小節以上のループでは、4小節ごとの区切りのうち休符が終わる位置以外にフィルを置き、ドラムのロールか主役の刻みのどちらかをSEEDで選ぶ（8小節以上のループの最後は両方）。フィルの最後の1拍では、ロールならドラムが直前の断片を16分音符4つで強くなるように連打し、刻みなら主役が直前の断片（音符のまとまりは最初の1音）を8分・16分・16分（「タン、タタ」）で鳴らす。選ばれなかったほうはそのまま鳴り、ベースと合いの手は鳴らさない。休符またはフィルの次の小節の頭では、主役・ベース・ドラムがAの1拍目の断片を、オクターブ移動と逆再生なし・強めの音量で鳴らす。breaksが0のときは休符もフィルも入れない。

`js/source-category.js` はファイル名からドラムを分類し、手動指定を優先する。分類の変更はキー設定や元の断片配置を保持する。

`js/playback-plan.js` は元の配置を保ったまま、ドラムとその他それぞれの同時発音数を制限する。発音枠と同時刻の選択順を分類ごとに管理し、片方の上限変更はもう片方の配置に影響しない。波形表示と音声処理で同じ計画を使う。`js/audio-engine.js` はWeb Audioで音声をレンダーし、プレビューとWAV書き出しには同じバッファを使用する。オクターブ移動の確率はoctaveで指定し、motionによる逆再生と独立して抽選する。どちらの変更でも断片の位置や選び方は保持する。キー同期の半音補正とoctaveのオクターブ移動は再生速度にも影響する。

PITCH ENVは断片ごとに上下方向を決め、指定した半音幅から基準ピッチへ戻す。方向は保存された断片の情報から決め、再生・書き出し・エンベロープ設定の変更で再抽選しない。発生の有無、振れ幅、戻る時間のばらつきも同じ断片情報から別々に抽選する（FNV-1aのハッシュを種にMulberry32を1回更新）。断片情報の位置は小節内の位置（16で割った余り）を使うため、繰り返す小節では同じようにかかる。「振り直す」は種の文字列を断片情報に加え、フレーズを変えずに別のかかり方を選ぶ（空なら従来どおり）。パートごとの発生確率は抽選値との比較だけで決めるため、確率を上げても既存の断片の形は変わらない。幅のばらつきは設定した最大幅から下方向に半音単位で広げ（最小1半音）、時間のばらつきは対数で上下対称（最大4倍）に広げて5〜500 msに収める。ばらつきで長くなる場合は、設定値と断片の長さの70%のうち長いほうを上限にする。`js/pitch-envelope.js` が再生速度とソースの読み出し位置を計算し、音声処理と波形表示で共有する。素材や生成イベントは変更せず、LOCK中にも適用する。

デモ音源は `js/audio-engine.js` で合成する。アーティストの録音素材は同梱していない。

FM音源は `js/fm-synth.js` で2オペレーターの位相変調として合成する。コード進行（I、I–IV、I–V、vi–IV、IV–V–iii–vi、vi–IV–V–I）は1小節に1つのコードをメジャースケールの度数で持つ。2小節分のリズムと動きの向きを1回だけ抽選し、各2小節に対してその小節のコードで音高を決め直す。最初の音はルート、それ以降の小節の頭は、オクターブ1〜2ならルート、それより高ければ3度45%・5度35%・ルート20%のうち直前の音に近いもの、4分音符の位置は抽選した向きで最も近いコードの音（約16%はコードの7度）、その間の16分音符は1〜2音の順次進行・刺繍音・同音とし、0〜9度（1オクターブ＋3度）に収める。音高は抽選済みの値だけから決めるため、進行を変えてもリズム・長さ・強さは変わらない。各音には小節のコードを記録し、`noteSegments` で素材に渡す。

生成器は、素材リストで最初のFM音源の進行をループのコードとする。音符のまとまりを別の小節に置くときは、元フレーズの2小節周期で同じ位置にあり、その小節のコードの上で書かれた音（フレーズ自身の移し替え）を最優先し、次にそのコードの上で書かれた同じコード内の位置（コードのルートからの音階上の距離）の音、同じ位置の音、元の位置に近い音の順で置き換える。ベースの小節頭と休符・フィル後の着地ではルートを最優先する。リズム・強さ・オクターブは変えない。FMの強さの初期値は0で、変調なしのピュアなサイン波になる。合成時は各音を最低1周期かけて立ち上げ、1.5周期かけて閉じる。FM音源のレーンで音の途中で切れる断片は終わりを30 msの直線フェードで閉じ、低いサイン波のクリックを抑える。最後まで鳴る断片と他の素材は従来どおり6 ms。
