# 処理方式と出典

更新日: 2026-10-02（日本時間）

## キーの判定と同期

キー情報は手動指定、ファイル名、音声解析の順に優先する。ファイル名では音名・長短調、異名同音、Camelot、Unicodeの変化記号を扱い、曖昧な名前は音声解析へ回す。

音程付き素材はメジャー基準に揃える。マイナーは平行調のメジャーに読み替え（A minor → C major）、元の判定情報を保持する。この読み替え自体では音程を変えない。単音・長短不明のルートは、同じルートのmajorを処理上の基準にする。

キー同期では素材と合わせ先の主音間の最短の半音差を計算する。ちょうど6半音の場合は下方向を選ぶ。ファイル名・手動指定・音声推定のいずれも同じ計算を使い、素材全体に同じ補正を適用する。解析でキーを保留した素材は自動移調しない。

自動の合わせ先はユーザー素材をデモより優先し、その中で長短調が分かる素材と明示されたキーを優先する。選ばれた基準素材自体は移調しない。合わせ先は手動でも指定できる。

例えばA minorはC major基準なので、合わせ先C majorなら0半音、D majorなら＋2半音となる。素材全体の移調では、素材内の長短関係やコード進行は変わらない。

## 音声解析

`js/key-analysis.js` は、窓をかけた音声のFFT、スペクトルのピーク検出、12音の分布（chroma）、キーのプロファイルとの照合を組み合わせる。chromaは音声から元のキーを推定する段階で用いる。

- FFTには **fft.js 4.0.4（MIT）** を使用する。上流本文にブラウザ用の接続部分とMIT表示を加え、`vendor/fft.js/fft.js` に同梱する。固定コミット、取得元、ハッシュは [provenance.json](../vendor/fft.js/provenance.json)、ライセンス全文は [LICENSE](../vendor/fft.js/LICENSE) に記録する。
- キーの重みにはPartitura v1.2.1掲載のKrumhansl–Kessler profilesを使用する。major/minor各12個、計24個の数値をJavaScript配列に転記し、数値は変更していない。取得元、著作権表示、変更範囲、Apache-2.0の利用条件は [第三者表示](../THIRD_PARTY_NOTICES.md#krumhanslkessler-profiles--partitura) に記載する。
- スペクトルのピークから音高クラス分布を求める方式は、Essentiaの [HPCP](https://essentia.upf.edu/reference/std_HPCP.html) と [Key](https://essentia.upf.edu/reference/std_Key.html) の説明を参考にする。Essentiaのライブラリ、WASM、C++ソースは同梱・読み込みしていない。

## フレーズ生成と再生

`js/generator.js` は素材と設定、SEEDから断片の配置を生成する。1〜2小節のモチーフを反復し、後半に変化を付ける。LOCKされたレーンは元の配置を保持する。乱数更新に使用するMulberry32の出典と利用条件は [第三者表示](../THIRD_PARTY_NOTICES.md#mulberry32) に記載する。

`js/source-category.js` はファイル名からドラムを分類し、手動指定を優先する。分類の変更はキー設定や元の断片配置を保持する。

`js/playback-plan.js` は元の配置を保ったまま、ドラムとその他それぞれの同時発音数を制限する。発音枠と同時刻の選択順を分類ごとに管理し、片方の上限変更はもう片方の配置に影響しない。波形表示と音声処理で同じ計画を使う。`js/audio-engine.js` はWeb Audioで音声をレンダーし、プレビューとWAV書き出しには同じバッファを使用する。オクターブ移動の確率はoctaveで指定し、motionによる逆再生と独立して抽選する。どちらの変更でも断片の位置や選び方は保持する。キー同期の半音補正とoctaveのオクターブ移動は再生速度にも影響する。

PITCH ENVは断片ごとに上下方向を決め、指定した半音幅から基準ピッチへ戻す。方向は保存された断片の情報から決め、再生・書き出し・エンベロープ設定の変更で再抽選しない。発生の有無、振れ幅、戻る時間のばらつきも同じ断片情報から別々に抽選する（FNV-1aのハッシュを種にMulberry32を1回更新）。パートごとの発生確率は抽選値との比較だけで決めるため、確率を上げても既存の断片の形は変わらない。幅のばらつきは設定した最大幅から下方向に広げ、時間のばらつきは対数で上下対称（最大4倍）に広げて5〜500 msに収める。`js/pitch-envelope.js` が再生速度とソースの読み出し位置を計算し、音声処理と波形表示で共有する。素材や生成イベントは変更せず、LOCK中にも適用する。

デモ音源は `js/audio-engine.js` で合成する。アーティストの録音素材は同梱していない。

配布に必要な表示は [第三者表示](../THIRD_PARTY_NOTICES.md)、確認とソースZIP作成の手順は [公開用ソースの作成](publication.md) を参照。
